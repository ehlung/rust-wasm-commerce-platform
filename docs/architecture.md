# Architecture

## 실행 경계

Host Runner는 운영체제와 네트워크에 접근할 수 있는 일반 Rust 프로세스입니다. Wasm 컴포넌트는 Wasmtime 샌드박스에서 실행되며 DB 소켓이나 자격증명에 직접 접근하지 않습니다.

```text
Wasm Component
  └─ product-repository.list() 같은 WIT 함수 호출
         ↓
Host Runner의 trait 구현
  └─ PostgreSQL Connection Pool에서 연결 획득
         ↓
SQL 실행 후 WIT record로 결과 반환
```

이 구조의 핵심은 **Wasm이 외부 자원에 임의로 접근하는 것이 아니라 Host가 계약으로 공개한 기능만 사용하는 것**입니다. 현재 저장소 기능은 상품, 재고, 주문 도메인별로 분리해 각 컴포넌트가 필요 이상의 DB 기능을 받지 않게 했습니다.

## 주문 트랜잭션

주문 컴포넌트가 입력을 검증하고 견적을 요청하면 Host Runner가 PostgreSQL에서 현재 가격과 재고를 확인합니다. 주문 확정 시에는 하나의 트랜잭션 안에서 다음 작업을 처리합니다.

1. 상품 행 잠금과 가격·재고 재확인
2. 주문 및 주문 항목 저장
3. 상품 재고 차감
4. 전체 성공 시 commit, 하나라도 실패하면 rollback

주문 취소도 주문 상태 변경과 재고 복원을 하나의 트랜잭션으로 처리합니다.

## MSA로 발전시키는 경계

현재는 모든 컴포넌트가 하나의 Host Runner 프로세스와 `8091` 포트를 공유합니다. 컴포넌트 코드는 분리되어 있지만 배포·장애·확장 단위는 하나이므로 MSA가 아니라 모듈형 백엔드입니다.

다음 단계에서 주문 영역을 별도 Host Runner와 포트로 분리하면 프로세스 단위 독립 실행·배포를 연습할 수 있습니다. 같은 Lightsail 서버에서는 서버 장애를 공유하며, 완전한 장애 격리와 독립 확장은 별도 VM 또는 컨테이너 배포 단계에서 확보합니다.
